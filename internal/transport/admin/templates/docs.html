Before you start

  1. Install the SDK in your web, mobile or Node.js project: npm install warden-auth. Every example also shows the plain HTTP call, so any language works.
  2. Create a publishable key for each app and a secret key for each backend on API keys. {{if .PK}}This instance already has {{.PK}}.{{end}}
  3. Add your web app's origin to its publishable key (or to Settings) so browsers may call {{.PublicURL}}.

Create the first user

From a backend or a one-off script, with a secret key. Unlike sign-up, this works even when sign-ups are off, and can assign roles, so it is how you create your first admin.

curlcurl -X POST {{.PublicURL}}/v1/server/users \
  -H "Authorization: Bearer $WARDEN_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{"email":"ada@example.com","password":"correct horse battery staple",
       "name":"Ada","roles":["admin"],"email_verified":true}'
Node.jsimport { createWardenServer } from "warden-auth/server";

const warden = createWardenServer({
  url: "{{.PublicURL}}",
  secretKey: process.env.WARDEN_SECRET_KEY,
});

const ada = await warden.users.create({
  email: "ada@example.com",
  password: "correct horse battery staple",
  name: "Ada",
  roles: ["admin"],
  emailVerified: true,
});

Sign a user in

In the app. In browsers, cookie mode keeps the refresh token in an HttpOnly cookie; the SDK keeps the access token in memory and refreshes it before it expires.

curlcurl -X POST {{.PublicURL}}/v1/auth/signin \
  -H "X-Warden-Key: {{$pk}}" \
  -H "Content-Type: application/json" \
  -d '{"email":"ada@example.com","password":"correct horse battery staple"}'

# → {"status":"authenticated","tokens":{"access_token":"…",
#    "refresh_token":"…"},"user":{…}}
# or {"status":"mfa_required","mfa_token":"…"}

Upload a profile photo

JPEG, PNG, GIF or WebP up to the configured size. Warden decodes the image, strips metadata, resizes it and re-encodes it as JPEG before storing it in S3.

curlcurl -X PUT {{.PublicURL}}/v1/me/avatar \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "file=@photo.jpg"

# → user with "avatar_url"

Check a role in your API

Your API verifies the access token itself with the public keys, so no call to Warden is needed per request. Roles are in the token; change them with the server API or on the user's page.

Expressimport { createWardenServer } from "warden-auth/server";

const warden = createWardenServer({
  url: "{{.PublicURL}}",
  issuer: "{{.Issuer}}",
  audience: "{{.Audience}}",
});

app.get("/admin/reports",
  warden.express({ roles: ["admin"] }),
  (req, res) => res.json({ hello: req.auth.userId }));

// Anywhere else:
const claims = await warden.verifyToken(token);
if (!claims.roles.includes("admin")) { /* 403 */ }

React to new and updated users

Add an endpoint on Webhooks and verify each request with its signing secret.

Expressimport { verifyWebhook } from "warden-auth/server";

app.post("/webhooks/warden",
  express.raw({ type: "application/json" }),
  async (req, res) => {
    const event = await verifyWebhook({
      secret: process.env.WARDEN_WEBHOOK_SECRET,
      headers: req.headers,
      body: req.body, // raw bytes, not parsed JSON
    });
    if (event.type === "user.created") { /* … */ }
    res.sendStatus(204);
  });

Admin API for automation and AI agents

Everything you do in this admin UI can be scripted, or handed to an AI agent, with an access token: scoped per resource, expiring after at most 90 days, optionally pinned to IP ranges. It is served on this private admin port, not on the public API.

curlcurl {{.AdminURL}}/api/v1/email-templates/verify_email?lang=tr \
  -H "Authorization: Bearer $WARDEN_ACCESS_TOKEN"

# Change only the subject; HTML and text keep their value
curl -X PUT "{{.AdminURL}}/api/v1/email-templates/verify_email?lang=tr" \
  -H "Authorization: Bearer $WARDEN_ACCESS_TOKEN" \
