Sign-up and sign-in

Allow sign-ups

When off, nobody can create a new account, with a password or with a social provider. Existing users can still sign in.

Require email verification

Password users must click the link in their verification email before they can sign in.

Block breached passwords

Checks new passwords against Have I Been Pwned. Only the first 5 characters of a SHA-1 hash leave the server. Needs outbound internet.

8 to 64. Applies to new and changed passwords.

3 to 100. The account is locked for the lockout window after this many wrong passwords.

Apps that use this instance

One per line. Social sign-in returns only to these exact URIs (web pages or mobile app schemes).

One per line. Web apps on these origins may call the API from the browser. Origins added to a publishable key are allowed too. Mobile and server apps need nothing here.

Require a publishable key

Reject public API calls that do not send a valid X-Warden-Key. Create keys on the API keys page and set them in your apps first, or they stop working.

Emails

Shown in email subjects and in authenticator apps.

A page in your app that posts the {token} to /v1/auth/email/verify.

A page in your app that asks for a new password and posts it with the {token}.

Language

Used for users who have not picked a language. A user's language is set from the app (locale on sign-up or PATCH /v1/me), from their browser's language on sign-up, or on their page here. Edit the wording per language under Emails.

Security notifications

Sign-in from a new device

Email the user the first time their account signs in from a browser or app it has not used in 180 days: device, IP, country (behind Cloudflare or a similar proxy), method and time, with a button that ends that session. A new account's first device never triggers it. At most 3 per account per hour.

Account locked

Email the user once when wrong passwords reach the lockout threshold, so they learn someone is guessing.

Password and two-factor changes are always notified.
