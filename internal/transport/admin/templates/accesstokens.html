Use it with Claude

Warden ships an MCP server, so Claude Code, Claude Desktop and other MCP clients get tools like list users, edit email template or create webhook, limited to this token's permissions. Claude Code:

claude mcp add warden \
  -e WARDEN_ADMIN_URL={{.AdminURL}} \
  -e WARDEN_ACCESS_TOKEN=wat_... \
  -- warden mcp

Needs the warden binary on that machine: go install github.com/fatihacan1/warden/cmd/warden@latest, or run it from the image with docker run -i --rm --network host -e WARDEN_ADMIN_URL -e WARDEN_ACCESS_TOKEN warden mcp. The admin port must be reachable from there (locally, over a VPN or an SSH tunnel).

Claude Desktop (claude_desktop_config.json):

{
  "mcpServers": {
    "warden": {
      "command": "warden",
      "args": ["mcp"],
      "env": { "WARDEN_ADMIN_URL": "{{.AdminURL}}", "WARDEN_ACCESS_TOKEN": "wat_..." }
    }
  }
}

Any other tool can call the API directly:

curl {{.AdminURL}}/api/v1/email-templates/verify_email?lang=en \
  -H "Authorization: Bearer $WARDEN_ACCESS_TOKEN"

All endpoints are listed under API docs.

How tokens are protected

  • Every token expires. The longest is 90 days; there is no “never”.
  • Permissions are per resource and start empty. Read never includes write.
  • Only a SHA-256 hash is stored. Each request is checked against the database, so revoking works at once on every replica.
  • The admin API listens on this private port only, behind the same IP allowlist as this UI, and refuses browser requests.
  • A token cannot create tokens or change admin access, so a leaked one cannot escalate or lock you out.
  • 300 requests per minute per token, and every change is in the audit log with the token's name.
