How a service gets a token

curl -u "$CLIENT_ID:$CLIENT_SECRET" \
  -d grant_type=client_credentials \
  -d scope="orders:read" \
  -d audience=orders-api \
  {{.PublicURL}}/v1/oauth/token

The answer holds access_token, expires_in and scope. Send the token as Authorization: Bearer to the other service, which checks the signature with {{.PublicURL}}/.well-known/jwks.json, the issuer, its own audience and the scope claim. The token has sub: client:… and client_id but no user, so it is refused by every user endpoint.

  • Secrets are stored as SHA-256 hashes and shown once. Wrong secret, unknown client and revoked client all answer invalid_client.
  • A client can only ask for the scopes and audiences you list. Without a scope it gets all of its scopes; without an audience it gets the first one listed.
  • Rotate with the old secret kept for 1 or 24 hours, update your services, and the old one stops by itself.
  • Requests are rate limited per client and per IP, and issued tokens and failed attempts are in the audit log.
