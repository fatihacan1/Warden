Integrate an app

Values for this instance. Your backends verify access tokens offline; they never need to call Warden on each request.

1. Verify tokens in your backend

Node.js / Express with jose:

import { createRemoteJWKSet, jwtVerify } from "jose";

const JWKS = createRemoteJWKSet(new URL("{{.JWKS}}"));

export async function requireAuth(req, res, next) {
  const token = req.headers.authorization?.replace(/^Bearer /i, "");
  if (!token) return res.status(401).json({ error: "unauthorized" });
  try {
    const { payload } = await jwtVerify(token, JWKS, {
      issuer: "{{.Issuer}}",
      audience: "{{.Audience}}",
      algorithms: ["ES256"],
      typ: "at+jwt",
    });
    req.user = { id: payload.sub, sessionId: payload.sid, roles: payload.roles ?? [] };
    next();
  } catch {
    res.status(401).json({ error: "invalid_token" });
  }
}

Go with github.com/MicahParks/keyfunc/v3 and golang-jwt/jwt/v5:

jwks, _ := keyfunc.NewDefault([]string{"{{.JWKS}}"})
token, err := jwt.Parse(raw, jwks.Keyfunc,
    jwt.WithValidMethods([]string{"ES256"}),
    jwt.WithIssuer("{{.Issuer}}"),
    jwt.WithAudience("{{.Audience}}"))

2. Sign users in

Email and password

  1. POST {{.PublicURL}}/v1/auth/signup or /v1/auth/signin with {"email","password"}.
  2. If the response status is mfa_required, post the code to /v1/auth/mfa/verify.
  3. Refresh with POST /v1/auth/refresh. Each refresh token works once; always store the new one.

Social sign-in (web and mobile)

  1. Create a PKCE verifier and its S256 challenge in the app.
  2. Open {{.PublicURL}}/v1/oauth/<provider>/authorize?redirect_uri=…&code_challenge=…&code_challenge_method=S256&state=… (browser, ASWebAuthenticationSession or Custom Tabs).
  3. Your redirect URI receives ?code=…&state=…. Exchange it at POST /v1/oauth/token with code, code_verifier and redirect_uri.

Native Apple and Google

Send the ID token from the platform SDK to POST /v1/oauth/apple/native or /v1/oauth/google/native with {"id_token","nonce"}, where nonce is the raw nonce you generated (16+ chars).

Browser apps

Send X-Auth-Mode: cookie to receive the refresh token as an HttpOnly cookie instead of in the JSON body, and keep the access token in memory only.
